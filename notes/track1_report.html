Claim-Level Faithfulness to Experimental Results

A System Report and Empirical Study — NLPCC‑2026 Shared Task 10, Track 1

Qwen3‑VL‑8B + LoRA diverse‑model union|38 submissions|champion 50.26|2026‑06

Abstract.We document a systematic exploration of NLPCC‑2026 Shared Task 10, Track 1 (claim‑level faithfulness to experimental results), comprising 38 Codabench submissions and a leakage‑free offline evaluation bench. Our champion system — a five‑member diverse‑model union over Qwen3‑VL‑8B LoRA fine‑tunes — reaches a Phase‑1 score of 50.26 (best single model 47.80). Three findings are of methodological interest. (i) The task is recall‑critical, not precision‑critical: score is monotone in the count of correctly recovered minority sentences, and every suppression heuristic hurts. (ii) The choice between a PEM‑bottleneck (softmin) loss and plain cross‑entropy reverses sign with the oversampling regime — plain‑CE wins without oversampling, softmin wins with it — because softmin exists precisely to control the false positives that oversampling induces. (iii) An image‑disjoint, distribution‑reshaped offline bench can rank same‑condition models in the correct order but cannot predict absolute test scores nor extrapolate across training regimes. We catalogue the directions that failed (larger models, architecture diversity, density‑matched synthesis, suppression post‑processing, plain‑CE retraining) and distil the durable lessons, chief among them that the data prior over paragraph structure dominates model scale.

1 Task, Data, and Method

Introduction

We describe our system for NLPCC 2026 Shared Task 10, Track 1: Claim-level Faithfulness to Experimental Results. The task targets a fine-grained, sentence-level reliability problem in scientific communication: given a multi-sentence claim paragraph accompanied by figure/table evidence, each sentence must be assessed for how faithfully it reports what the evidence actually shows. Our system is based on Qwen3-VL-8B-Instruct fine-tuned with LoRA, trained with a custom softmin-PEM loss under minority oversampling, and assembled into a diverse-model union ensemble. Across 38 Phase-1 test (testp1) submissions on Codabench, the champion system (s15, five-member union) achieves a score of 50.26; the best single model (s01, grid) scores 47.80.

Task Definition

Each input record consists of: (1) a claim paragraph of pre-tokenised sentences (claim_text plus a sentence list), and (2) an evidence bundle of one or more figure or table items, each accompanied by a caption. The system must assign exactly one label per sentence, chosen from the following five categories:

LabelMeaning
SupportedThe sentence is fully supported by the evidence.
Unsupported Causal MechanisticThe sentence introduces a causal or mechanistic explanation that the evidence does not warrant.
Unsupported EntityThe sentence refers to a dataset, metric, model variant, or baseline not present in the evidence.
Scope OvergeneralizationThe sentence projects the conclusion beyond the scope the evidence supports.
ContradictionThe sentence is directly contradicted by the evidence.

Label strings must match exactly (including capitalisation and internal spaces). The submission format is JSONL: one object per record with fields id (copied verbatim from the test set) and labels (an ordered array whose length equals the sentence count for that record). Parse failures or out-of-vocabulary labels fall back to Supported.

The official evaluation metric combines two components computed by offline_eval/evaluate.py --track 1:

  • Sentence Macro-F1: five-class macro-averaged F1, weighting all classes equally.
  • PEM (Paragraph Exact Match): a paragraph scores 1 only when every sentence in it is correctly labelled.
  • Final score = (Macro-F1 + PEM) / 2.

For multi-label sentences (those with multiple valid gold types), a prediction is correct if it matches any gold label; the matched label is used as the F1 reference, otherwise the primary label types[0] is used.

The "≤1 minority per paragraph" pseudo-prior. In train-dev, among all long paragraphs (≥6 sentences), only 0.46% contain two or more minority sentences; across the full 3,333-record set, only 8 records carry ≥2 minorities. A model trained on this distribution learns a near-deterministic prior: at most one minority per paragraph. On testp1's minority-dense paragraphs this prior produces systematic under-recall — the root cause of all single-model performance limitations identified in this campaign.

Method

Base model. We fine-tune Qwen3-VL-8B-Instruct with LoRA (rank 16, alpha 32, all linear layers, ViT frozen) in bf16 precision using ms-swift 4.2.3. The image resolution is capped at max_pixels = 401408; increasing resolution to 802,816 was empirically harmful (s02: −3.3 points).

Training formats. We implement two input formats. In the per-sentence format, each training sample consists of a shared evidence/claim context plus a single TARGET sentence; the model outputs one label. The 3,333 records expand to ~17,547 per-sentence samples; at inference time, the shared prefix is KV-cache reused across the n sentences of the same record. In the paragraph-joint format, a single forward pass covers the full paragraph and the model outputs a JSON array of n labels; this is the only viable format for Qwen3-VL-32B-Instruct (per-sentence 32B repetition of image prefixes would require ~200 GiB VRAM). Per-sentence is the primary format for all union members.

Loss function. The per-sentence softmin-PEM loss (custom ms-swift integration) augments standard cross-entropy with a paragraph-level bottleneck: it up-weights the loss on the sentence within a paragraph that has the highest probability of being wrong, penalising configurations that would shatter PEM. Plain cross-entropy (plain-CE) is used for joint-format models and as an ablation. The two losses interact strongly with oversampling (see below).

Class-imbalance handling. Minority classes are oversampled and Supported is downsampled during dataset construction. The grid-optimal configuration (s01) uses minority oversample factor 3.0 and Supported downsample factor 0.6. For multi-label sentences the minority label is selected as the training target (preferring minority over Supported). Splits are made at the record level (9:1 stratified by minority presence) to prevent sentence-level leakage and preserve PEM validity on the dev set.

Ensemble strategy. The union ensemble (scripts/ensemble_union.py --min-votes 1) combines predictions from multiple independently trained models: a sentence receives a minority label if any member fires it. This is strictly recall-additive, simultaneously lifting both Macro-F1 and PEM when members are sufficiently diverse and individually competent. The champion system s15 combines five Qwen3-VL members trained with varied oversample rates and formats.

Key insight — softmin vs. plain-CE regime reversal: Without oversampling, plain-CE outperforms softmin (s32 38.68 > s31 34.21, +4.47). With the real oversampling recipe (full train-dev, minority oversample 3×), softmin dominates at both the single-model level (s01 47.80 > s33 42.87, +4.93) and the union level (s15 50.26 > s37 48.54, +1.72). The mechanism: oversampling causes plain-CE to over-fire minority predictions, generating false positives that shatter PEM on long paragraphs; softmin's PEM-bottleneck loss suppresses exactly those oversampling-induced false positives. A finding from a no-oversample or reduced-data regime cannot be safely extrapolated to the full training recipe.
Key insight — recall-critical inversion: The initial framing of the task as precision-critical (suppress minorities to protect PEM) was derived from the train-dev trivial score of 43.2 and was overturned by the first testp1 submissions. On testp1, every minority-suppression intervention (veto, confidence threshold, ≥2-vote consensus, reduced oversample) monotonically decreased the score. The suppression sweep measured on testp1 — 46 minority predictions → 18.85, 127 → 38.48, 171 → 39.57, 190 → 43.85, 253 → 47.80 — confirms that score is monotone in the count of correctly fired minority labels. PEM is recall-limited, not precision-limited, on the long minority-dense test paragraphs.

2 Results: the Recall-Critical Inversion and the Union Lever

The Recall-Critical Inversion

The initial experimental framing assumed testp1 was precision-critical: the train-dev trivial baseline (all-Supported) scores 43.2, suggesting that preserving clean paragraphs for PEM should take priority over minority-class recall. This framing was falsified on first contact with the leaderboard. The testp1 all-Supported trivial scores only 18.85 (s05), reflecting a fundamentally different distribution: paragraphs are long (mean 8.7 sentences, maximum 31), and approximately 84% of paragraphs contain at least one gold minority-class sentence. In this regime PEM is recall-limited, not precision-limited — a paragraph receives PEM=1 only when every gold minority label is correctly predicted, so missing even one minority label in a long paragraph guarantees PEM=0 for that paragraph.

The suppression sweep makes the monotone relationship explicit. Starting from the best single model (s01, grid softmin), progressively suppressing minority predictions yields a strictly decreasing score trajectory:

Score is monotone in the count of correct minority predictions. Every suppression mechanism — veto, confidence threshold, lower oversampling ratio, or ≥2-vote consensus — monotonically hurts testp1 score.

This inversion (suppression sweep: 46 minorities → 18.85; 127 → 38.48; 171 → 39.57; 190 → 43.85; 253 → 47.80) establishes that the winning objective is maximizing correct minority recall, not controlling minority precision. The post-processing methods (s03–s07) were accordingly abandoned; all subsequent work focuses on increasing recall additively.

The Diverse-Union Lever

Given that recall is the binding constraint, the ensemble strategy is to take the union over independently trained models: a sentence is assigned a minority label if any member fires it. This is implemented via ensemble_union.py --min-votes 1. Adding diverse members is recall-additive: each new model that makes independent errors on different minority sentences increases the count of correctly recalled minorities, lifting both Macro-F1 and PEM simultaneously.

The scaling from single model to five-member union is strictly monotone:

  • s01 — 1 member (grid softmin): 47.80 (best single; 253 minorities)
  • s11 — 3 Qwen members (s01 + s08 + s09): 48.22 (339 minorities)
  • s14 — 4 Qwen members (+ s13 joint-32B): 49.99 (365 minorities)
  • s15 — 5 Qwen members (+ s12 joint-8B): 50.26 ★ CHAMPION (382 minorities)

Both Macro-F1 and PEM rise together at each step (MF1: 52.77 → 54.80 → 56.80 → 57.17; PEM: 42.83 → 41.64 → 43.17 → 43.34), confirming that the minority recalls being added are predominantly correct rather than spurious.

Member-Quality and Correlation Caveat

The union benefit depends critically on both member quality and error independence. Experiments adding weaker or correlated members consistently show the same failure mode: Macro-F1 increases (more minorities fired) but PEM decreases (false-positive minorities shatter clean paragraphs), for a net score loss. Representative cases:

  • s18 (+Qwen3-VL-4B, same architecture, weaker): MF1 +0.11, PEM −1.19 → score 49.71 (−0.55 vs s15)
  • s20 (+InternVL3-8B, architecture-diverse): MF1 +0.57, PEM −1.36 → score 49.36
  • s23 (+Gemma4-26B, architecture-diverse, nearest miss): MF1 57.67 (+0.50 vs s15), PEM 41.98 (−1.36) → score 49.83
  • s27 (Gemma4-31B single): only 87 minorities fired → score 29.28, confirming that model scale alone cannot overcome the training-data prior

The consistent pattern — recall gain offset by PEM loss — indicates that the 5-Qwen union (s15) has already captured most of the recoverable true minorities; adding a sixth member whose errors are partially uncorrelated from those of s15 but also introduces a new set of false positives yields no net benefit. s15 at 50.26 represents the ceiling of naive union scaling with the current training recipe.

3 GATE-B: Building (and Calibrating) a Leakage-Free Offline Bench

Motivation: Why the Naive Dev Split Fails

Throughout the campaign each new idea consumed one Codabench submission (100-shot budget, Phase-1 test set). A reliable offline proxy would multiply iteration speed. The obvious candidate — a held-out slice of train-dev — fails on three independent counts.

  • Image leakage (32%). A random 90/10 record split does not respect the fact that multiple records share the same evidence figure (identified by image SHA). Approximately 32% of dev records contain at least one image whose SHA also appears in the training split, so the model has already seen the visual evidence at training time. Scores on such a dev are inflated by memorization.
  • Domain and size mismatch. The naive 88-record random dev used for early model selection was small and unrepresentative; more importantly, its paragraph distribution mirrors train-dev (mean 5.1 sentences, 34.5% of records containing any minority-label sentence) rather than testp1 (mean 8.7 sentences, ~84% minority-carrying paragraphs). A model evaluated in the train-dev regime receives misleading feedback.
  • Wrong suppression regime — the suppression trap. The all-Supported trivial baseline on the raw image-disjoint dev scores 42.37 with PEM ~65. In this regime, suppressing minority predictions improves the dev score, reinforcing a "precision-critical" framing that was already falsified on testp1 (all-Supported trivial ≈ 18.85). Any dev that rewards minority suppression is anti-correlated with what actually matters on testp1.

Densematch Construction

GATE-B (Phase A) built a leakage-free offline bench through two steps applied in sequence.

Step 1 — Image-disjoint split. Records were partitioned using union-find over shared image SHAs (build_dataset --split-mode component_aware --val-ratio 0.15 --seed 42), ensuring that every image SHA in the dev partition is absent from the training partition. The result: 2,832 train records (data/devbench/train_sft.jsonl) and 501 dev records with zero SHA overlap — the zero-SHA assertion was verified programmatically.

Step 2 — Testp1-shape reshaping. The raw 501-record image-disjoint dev retains the train-dev shape and therefore the suppression trap. scripts/reshape_devbench.py produced three gold variants: raw (501 records, control), reshaped (records ≥8 sentences with ≥84% minority density, severely pool-limited to ~30 records), and densematch (206 records, minority density forced to exactly 84% without a hard length floor, balancing statistical power against shape fidelity). However, two extrapolation failures are equally instructive. First, absolute scores are not transferable: densematch scores run ~40 points higher than testp1 (offset ≈ 40), ruling out any use of the bench for predicting raw testp1 performance. Second, the bench cannot extrapolate across training regimes. Epistemics: A Same-Condition Ranker, Not a Selector

The durable lesson from GATE-B is a precise characterisation of what offline benches can and cannot do in this setting:

  • Can do: rank models trained under the same conditions (same data, same loss, same oversample regime) — the three clean Phase-C points confirm this; kill large bad directions offline (higher image resolution, minority suppression, 2-epoch overfit all tank densematch and would have saved one Codabench shot each).
  • Cannot do: predict absolute testp1 scores (offset ~40 pts); extrapolate across regimes (train' vs full-traindev, oversampled vs not, joint vs per-sentence format); rank the union top (500-record bench is underpowered for the 0.3–0.5 pt differences at the leaderboard apex).
An offline bench built on image-disjoint, testp1-shaped data is a same-condition ranker. It can kill bad directions cheaply and confirm relative ordering within a fixed regime, but it cannot substitute for real leaderboard evaluation when comparing candidates across training regimes or when resolving sub-half-point differences at the top.

The cumulative protocol (Phase C) is the clean long-term resolution: every new candidate is trained on the image-disjoint train', scored on densematch offline, and simultaneously submitted to Codabench. Each such pair tightens the rank-correlation estimate without leakage, and the first density-matched model simultaneously serves as the breakthrough candidate (P1). The bench's trustworthiness grows with the number of clean calibration points rather than depending on legacy adapters that cannot be de-leaked after the fact.

4 The softmin ⇄ plain-CE Regime Reversal

A recurring hazard in this campaign was the sign-reversal: an experimental conclusion reached under one set of conditions flipped when a single upstream variable changed. The softmin-PEM loss vs. plain cross-entropy (plain-CE) comparison delivered the sharpest instance, reversing direction three times across three cleanly separated regimes.

Background: the two losses

The custom softmin-PEM loss (integrated into ms-swift 4.2.3) adds a paragraph-level bottleneck term to the per-token CE objective. Its design intent is to penalise the model for producing any false-positive minority prediction in an otherwise-correct paragraph, thereby protecting Paragraph Exact Match (PEM). Plain-CE is the standard per-token cross-entropy with no such paragraph-aware regularisation.

Reversal 1 — image-disjoint train', no oversampling (GATE-B PHASE C bench)

In PHASE C, both losses were trained on data/devbench/train_sft.jsonl: an image-disjoint 85 % split of train-dev (train') with no minority oversampling. On the densematch offline bench the plain-CE model (A1) scored 81.13 vs. softmin (A0) 78.97 — a +2.16 gap favouring plain-CE. The same ordering held on testp1 (s32 plain-CE 38.68 vs. s31 softmin 34.21, +4.47), confirming the bench direction. Without oversampling, plain-CE wins.

Reversal 2 — full train-dev with oversampling (the real recipe)

Having confirmed plain-CE > softmin on clean models, the natural next step was to retrain s15's per-sentence members as plain-CE on the full train-dev with oversampling (s01 recipe: --minority-oversample 3.0 --supported-downsample 0.6). The result reversed completely:

Reversal 3 — architecture interaction (Gemma-4-26B)

A third, even larger reversal emerged for a different architecture. Gemma-4-26B trained with softmin scored 44.69 (s26). The same architecture retrained with plain-CE produced only 21.40 (s36), predicting just 46 minority sentences and collapsing to near-trivial performance. Whereas Qwen3-VL plain-CE over-fires minorities under oversampling, Gemma plain-CE catastrophically under-fires them — demonstrating that the loss × model × oversampling interaction cannot be extrapolated across architectures.

Mechanism: why softmin only pays off under oversampling

Oversampling duplicates minority sentences by a factor of 3–6×, which systematically biases the gradient signal toward minority classes. In plain-CE this bias translates directly into an elevated minority-class activation rate at inference time: the model fires minorities liberally, producing false positives that shatter otherwise-correct paragraphs and collapse PEM. The softmin-PEM loss counters exactly this effect: its paragraph-level penalty suppresses the oversampling-induced FP surplus, recovering PEM while preserving true-positive minority recall. When there is no oversampling (PHASE C train' models), minority frequency is low, FP risk is low, and the bottleneck penalty is unnecessary overhead — hence plain-CE wins.

The softmin loss earns its keep if and only if minority oversampling is active. Any clean-bench or no-oversample finding about the two losses is a regime-conditioned signal and must be re-validated on the full real recipe before acting on it.

Per-class recall bottleneck

The shortfall is instead attributed to the train-dev pseudo-prior discussed in Section 3: of the 3333 training records, only 8 carry ≥2 minority sentences, and of long paragraphs (≥6 sentences) only 0.46 % do. The model internalises an implicit "at most one minority per paragraph" rule, which systematically suppresses recall in testp1's minority-dense long paragraphs. The union ensemble partially compensates — s15 fires 382 minority predictions vs. s01's 253, lifting PEM and Macro-F1 simultaneously — but the Contradiction recall bottleneck (~22 %) persists across all 38 submitted systems.

The fundamental recall bottleneck is not a loss or oversampling artefact but a training-data prior: the near-absence of multi-minority paragraphs in train-dev teaches a near-deterministic "≤1 minority per paragraph" heuristic that no loss function alone can overcome.

5 What Died, What Worked, and Open Levers

What Worked

  • Diverse-model union ensemble (recall-additive). Combining independently trained Qwen3-VL-8B members with ensemble_union.py --min-votes 1 is the only lever that has monotonically improved over the best single model across every addition: s01 47.80 (1 member) → s11 48.22 (3) → s14 49.99 (4) → s15 50.26 (5). The gain is simultaneous in Macro-F1 and PEM because on testp1's minority-dense paragraphs PEM is recall-limited: catching a gold minority sentence that was missed by all other members turns a zero-PEM paragraph into a candidate for PEM=1. Consensus (≥2 votes, s16=47.29) consistently underperforms, confirming that suppression destroys more correct recalls than it eliminates false positives.
  • Softmin-PEM loss under oversampling. The custom softmin-PEM bottleneck loss earns its keep precisely under the real training recipe (minority oversampling + Supported downsampling): it controls the oversampling-induced false-positive explosion that plain cross-entropy produces. With full-traindev + oversampling, softmin beats plain-CE by +4.93 at single-model level (s01 47.80 vs s33 42.87) and +1.72 at union level (s15 50.26 vs s37 48.54). The mechanism is PEM: s33 PEM=37.03 vs s01 PEM=42.83 — plain-CE over-fires minorities and shatters clean paragraphs.
  • The recall-critical recipe. Maximising the count of correct minority predictions is the monotone objective. The suppression sweep makes this concrete: forcing minorities to zero yields the all-Supported trivial (s05=18.85); every incremental restoration of correct minority calls raises score monotonically — 46 minorities→18.85, 127→38.48, 171→39.57, 190→43.85, 253→47.80. The key insight is that testp1 paragraphs are long (mean 8.7 sentences, max 31) and minority-dense (~84% of paragraphs carry at least one gold minority), so PEM improvement requires catching those minorities, not protecting clean paragraphs by suppressing predictions.

Durable Lessons

The data prior beats model scale. The training set contains a near-deterministic "at most one minority per paragraph" pattern (≤1 minority in 99.54% of long paragraphs; the full 3333-record set has only 8 records with ≥2 minority sentences). Every model — regardless of size or architecture — learns this prior. A Gemma4-31B trained on the same data is more conservative than an 8B model, not less, producing only 87 minority predictions and scoring 29.28. Scaling model capacity without changing the training signal cannot break the recall ceiling.
Recall-critical PEM: the suppression trap is metric-specific. PEM rewards entire paragraphs only when every sentence label is correct. On train-dev (short paragraphs, trivial=43.2) PEM is dominated by clean all-Supported paragraphs — suppressing minorities protects those paragraphs and raises PEM. On testp1 (long paragraphs, trivial≈18.85, ~84% minority-carrying) the same suppression destroys PEM because the missed minority sentences prevent the paragraph from ever reaching PEM=1. Any benchmark or framing derived from train-dev statistics will produce the wrong suppression recommendation for testp1.
  • The offline benchmark (densematch) is a same-condition ranker, not a selector. The image-disjoint, testp1-shaped dev split (GATE-B) correctly ranks models trained under identical conditions: softmin < plain-CE < union on both densematch (78.97 < 81.13 < 83.90) and testp1 (34.21 < 38.68 < 43.85). However it cannot predict absolute testp1 scores (offset ~40 points), and it mis-ranks across training regimes: it rated the joint-anchored clean union (s30) as the top candidate; on testp1 that union scored 43.85, below s01's 47.80. The offset is explained by full-traindev + oversampling being worth ~9–13 points over train'-only + no-oversample, a gap the bench does not model.
  • Re-validate clean-bench findings on the real recipe before concluding. The campaign produced three sign-reversals: (1) veto/suppression helpful on train-dev → harmful on testp1; (2) plain-CE > softmin on the clean no-oversampling bench → softmin > plain-CE on the real full-traindev + oversampling recipe (+4.93 single, +1.72 union); (3) the joint format beating per-sentence on densematch → the union led by a joint member underperforming on testp1. Every clean-bench finding should be treated as a hypothesis requiring testp1 confirmation before committing training resources.

Standing Best and Open Levers

The permanent performance floors are s15 (5-Qwen union) at 50.26 (MF1=57.17, PEM=43.34) and s01 (single model, softmin grid) at 47.80 (MF1=52.77, PEM=42.83), both trained on full train-dev with minority oversampling and the softmin-PEM loss. These represent 38 Codabench submissions and 17 LoRA adapters.

The remaining recall bottleneck is class-specific: Supported recall ≈99.5%, Unsupported Causal Mechanistic ≈100%, Unsupported Entity ≈86%, Scope Overgeneralization ≈63%, Contradiction ≈22% (firing on roughly 2–4 of 9 gold instances). Contradiction and Scope Overgeneralization are the binding constraints on Macro-F1 and, consequently, on score.

Two directions have not been tested against testp1 and remain live:

  • Self-consistency on per-sentence softmin members. Phase-C demonstrated that self-consistency (temperature sampling + per-sentence union) adds +1.4 on the clean no-oversampling bench without adding correlated false positives. Applied to the existing s15 softmin members — which already have controlled PEM — this could provide additive minority recall, particularly for Contradiction and SO, without the false-positive explosion observed when applying self-consistency to joint models.
  • Additional seed-diverse softmin Qwen members. The monotone scaling from s01 to s15 was driven entirely by five Qwen3-VL-8B softmin models trained with different oversample configurations (grid / os4 / per-class / joint-8B / joint-32B). Retraining with additional seeds or oversample variants while keeping the softmin-PEM loss and full-traindev recipe may extend the scaling, given that each new member reduces the zero-recall instances for Contradiction and SO without adding the correlated noise of weaker architectures.

Forward Note

Phase 2 (hidden test set, released 2026-06-11, deadline 2026-06-20) introduces a distribution shift of unknown direction. The prior Phase-1 experience — where a benchmark calibrated on train-dev produced exactly the wrong suppression recommendation for testp1 — is a strong argument for prioritising robustness over further squeezing of Phase-1 score. The ensemble strategy is structurally robust: union members trained under different conditions cover different failure modes, and min-votes=1 ensures that each member's recall is additive. Candidates that score only marginally above s15 on testp1 but rely on configuration-specific tuning (resolution, oversample rate, architecture-specific loss schedules) carry higher Phase-2 risk than a wider, more diverse union that reaches the same score through orthogonal recalls.

1 引言

引言

本文描述我们参加 NLPCC 2026 共享任务 10 第一赛道——声明级忠实度（Claim-level Faithfulness to Experimental Results）——的系统。该任务针对科学传播中的细粒度、句子级可靠性问题：给定一段多句声明段落及其配套的图/表证据，需逐句评估每个句子对证据实际内容的忠实程度。我们的系统以 Qwen3-VL-8B-Instruct 为基础，使用 LoRA 进行微调，在少数类过采样下以自定义 softmin-PEM 损失训练，并组合成多样模型并集集成。在 Codabench 上共提交 38 次 Phase-1 测试（testp1）后，冠军系统（s15，五成员并集）取得分数 50.26；最佳单模型（s01，grid）得分 47.80。

任务定义

每条输入记录由以下两部分构成：（1）预分词句子组成的声明段落（claim_text 及句子列表），以及（2）一条或多条图或表组成的证据束，每条证据附有 caption。系统须对每个句子分配恰好一个标签，从以下五类中选取：

标签含义
Supported该句子被证据充分支持。
Unsupported Causal Mechanistic该句子引入了证据不能证明的因果或机制解释。
Unsupported Entity该句子提及了证据中未出现的数据集、指标、模型变体或 baseline。
Scope Overgeneralization该句子将结论外推至超出证据所支持的范围。
Contradiction该句子与证据直接矛盾。

标签字符串须逐字匹配（包括大小写与内部空格）。提交格式为 JSONL：每条记录对应一个对象，包含字段 id（原样复制自测试集）和 labels（有序数组，长度等于该记录的句子数）。解析失败或标签超出词表时回退为 Supported。

官方评测指标由 offline_eval/evaluate.py --track 1 计算，包含两个分量：

  • Sentence Macro-F1：五类等权 macro 平均 F1。
  • PEM（段落精确匹配）：仅当段落中每个句子均被正确标注时，该段落得分为 1。
  • 最终分数 = (Macro-F1 + PEM) / 2。

对于多标签句子（具有多个合法 gold 标签的句子），只要预测命中其中任意一个 gold 标签即视为正确；命中时以命中的标签作为 F1 参考，否则使用主标签 types[0]。

方法

基础模型。我们使用 LoRA（rank 16, alpha 32，所有线性层，ViT 冻结）对 Qwen3-VL-8B-Instruct 进行 bf16 精度微调，训练框架为 ms-swift 4.2.3。图像分辨率上限设为 max_pixels = 401408；将分辨率提升至 802,816 在实验中有害（s02：−3.3 分）。

训练格式。我们实现了两种输入格式。在逐句格式中，每个训练样本由共享的证据/声明上下文加单个 TARGET 句子构成，模型输出一个标签；3,333 条记录展开为约 17,547 个逐句样本，推理时同一记录的共享前缀在 n 个句子之间复用 KV-cache。在段落联合格式中，单次前向传播覆盖完整段落，模型输出包含 n 个标签的 JSON 数组；这是 Qwen3-VL-32B-Instruct 的唯一可行格式（逐句 32B 因重复图像前缀需约 200 GiB 显存）。逐句格式是所有并集成员的主要格式。

损失函数。逐句 softmin-PEM 损失（自定义 ms-swift 集成）在标准交叉熵之上引入段落级瓶颈：对段落内预测错误概率最高的句子上调损失权重，惩罚会破坏 PEM 的预测配置。段落联合格式模型及消融实验使用普通交叉熵（plain-CE）。两种损失与过采样之间存在强交互（见下文）。

类别不均衡处理。在数据集构造阶段对少数类进行过采样，对 Supported 进行下采样。grid 最优配置（s01）采用少数类过采样倍率 3.0、Supported 下采样因子 0.6。对于多标签句子，选取少数类标签作为训练目标（少数类优先于 Supported）。划分按记录级进行（9:1，按是否含少数类分层），以防止句子级泄漏并保证验证集上 PEM 的有效性。

集成策略。并集集成（scripts/ensemble_union.py --min-votes 1）融合多个独立训练模型的预测：只要任一成员对某句子触发少数类标签，该标签即被采纳。这是严格意义上的召回累加操作，在成员足够多样且各自具备能力时，可同时提升 Macro-F1 与 PEM。冠军系统 s15 融合了五个以不同过采样率和格式训练的 Qwen3-VL 成员。

关键发现——softmin 与 plain-CE 的机制反转：在不使用过采样时，plain-CE 优于 softmin（s32 38.68 > s31 34.21，+4.47）。而在真实过采样方案下（完整 train-dev，少数类过采样 3×），softmin 在单模型级别（s01 47.80 > s33 42.87，+4.93）和并集级别（s15 50.26 > s37 48.54，+1.72）均占优。其机制在于：过采样导致 plain-CE 过度触发少数类预测，产生的假阳性会破坏长段落的 PEM；而 softmin 的 PEM 瓶颈损失恰好抑制了这些由过采样诱发的假阳性。在无过采样或数据量减少的训练设置中得出的结论，不能安全外推至完整训练方案。
关键发现——召回关键的反转：最初将该任务定性为精度关键（抑制少数类以保护 PEM）的框架源自 train-dev 上 43.2 的平凡基线分数，并在首批 testp1 提交后被推翻。在 testp1 上，所有少数类抑制干预（veto、置信阈值、≥2 票共识、降低过采样）均单调降低分数。在 testp1 上测量的抑制扫描——46 条少数类预测→18.85，127→38.48，171→39.57，190→43.85，253→47.80——证实分数与正确触发的少数类标签数量单调正相关。在长段、少数类密集的测试段落上，PEM 是召回受限而非精度受限。

2 实验结果

召回关键的反转

最初的实验框架假设 testp1 是精度关键的：train-dev 的全-Supported trivial 基线得分为 43.2，这表明应将保持段落整洁以获得 PEM 置于少数类召回之上。然而这一框架在首次接触排行榜时即遭证伪。testp1 全-Supported trivial 实际仅得 18.85（s05），反映出截然不同的分布特征：段落较长（均值 8.7 句，最长 31 句），且约 84% 的段落至少包含一个 gold 少数类句子。在此训练设置下，PEM 受召回制约，而非受精度制约——只有当每个 gold 少数类标签均被正确预测时段落才能获得 PEM=1，因此在长段落中漏判哪怕一个少数类标签，都必然导致该段落 PEM=0。

抑制扫描实验清晰揭示了这种单调关系。以最优单模型（s01，grid softmin）为起点，逐步抑制少数类预测，分数呈严格递减趋势：

分数与正确少数类预测数量单调正相关。所有抑制机制——否决、置信阈值、降低过采样比例或 ≥2 票一致——均单调损害 testp1 分数。

这一反转现象（抑制扫描：46 个少数类 → 18.85；127 → 38.48；171 → 39.57；190 → 43.85；253 → 47.80）表明，最优目标是最大化正确的少数类召回，而非控制少数类精度。后处理方法（s03–s07）因此被放弃；后续所有工作均聚焦于以加法方式提升召回。

多样模型并集杠杆

鉴于召回是核心制约因素，集成策略采取对独立训练模型取并集的方式：若任意成员对某句子触发少数类标签，则该句子被赋予该标签。具体实现为 ensemble_union.py --min-votes 1。加入多样成员在召回上具有加法效应：每个新模型对不同少数类句子产生独立错误，从而增加被正确召回的少数类数量，使 Macro-F1 和 PEM 同步提升。

从单模型扩展至五成员并集的过程严格单调：

  • s01 — 1 个成员（grid softmin）：47.80（最优单模型；253 个少数类）
  • s11 — 3 个 Qwen 成员（s01 + s08 + s09）：48.22（339 个少数类）
  • s14 — 4 个 Qwen 成员（+ s13 joint-32B）：49.99（365 个少数类）
  • s15 — 5 个 Qwen 成员（+ s12 joint-8B）：50.26 ★ 冠军（382 个少数类）

每一步 Macro-F1 和 PEM 均同步上升（MF1：52.77 → 54.80 → 56.80 → 57.17；PEM：42.83 → 41.64 → 43.17 → 43.34），证实新增的少数类召回以真正确为主，而非假阳性。

成员质量与相关性注意事项

并集带来的收益在很大程度上取决于成员质量和误差独立性。加入质量较弱或相关性较高的成员的实验一致呈现相同的失败模式：Macro-F1 提升（触发更多少数类）但 PEM 下降（假阳性少数类打碎了整洁段落），最终导致净分数下降。典型案例如下：

  • s18（+Qwen3-VL-4B，相同架构，性能较弱）：MF1 +0.11，PEM −1.19 → 分数 49.71（较 s15 −0.55）
  • s20（+InternVL3-8B，架构多样）：MF1 +0.57，PEM −1.36 → 分数 49.36
  • s23（+Gemma4-26B，架构多样，最接近的失败案例）：MF1 57.67（较 s15 +0.50），PEM 41.98（−1.36）→ 分数 49.83
  • s27（Gemma4-31B 单模型）：仅触发 87 个少数类 → 分数 29.28，证实单靠模型规模无法克服训练数据伪先验

一致的规律——召回增益被 PEM 损失抵消——表明 5-Qwen 并集（s15）已捕获了大部分可恢复的真正少数类；若加入第六个成员，其误差与 s15 部分不相关，但同时也引入了一批新的假阳性，净收益为零。s15 的 50.26 代表了在当前训练方案下朴素并集扩展的上限。

3 离线评测台：构建、验证与认识论边界

动机：朴素验证集切分为何失效

整个参赛周期内，每个新想法都要消耗一次 Codabench 提交（Phase-1 测试集，上限 100 次）。若能获得可靠的离线代理指标，迭代速度将成倍提升。最直观的候选方案——从 train-dev 中保留一个验证切片——在三个独立维度上均告失败。

  • 图像泄漏（32%）。随机的 90/10 记录切分未能考虑到多条记录共享同一证据图（通过图像 SHA 标识）的情况。约 32% 的验证集记录中至少包含一张图像，其 SHA 也出现在训练切分中，意味着模型在训练时已见过该视觉证据。基于此类验证集的分数因记忆效应而虚高。
  • 领域与规模失配。早期用于模型选型的朴素 88 条记录随机验证集规模小且代表性不足；更关键的是，其段落分布与 train-dev 相似（平均 5.1 句，34.5% 的记录包含少数类标签句），而非 testp1（平均 8.7 句，约 84% 的段落含少数类句）。在 train-dev 机制下评估的模型会收到误导性反馈。
  • 错误的抑制机制——抑制陷阱。在原始图像不相交验证集上，全预测 Supported 的平凡基线得分为 42.37，PEM 约 65。在该机制下，抑制少数类预测反而提升验证集分数，强化了"精度关键"这一框架——而该框架在 testp1 上早已被推翻（全 Supported 平凡基线 ≈ 18.85）。任何奖励少数类抑制的验证集，均与 testp1 上真正重要的指标反相关。

Densematch 构建

GATE-B（Phase A）通过依次执行两个步骤，构建了一个无泄漏离线评测台。

第一步——图像不相交切分。使用基于共享图像 SHA 的并查集对记录进行划分（build_dataset --split-mode component_aware --val-ratio 0.15 --seed 42），确保验证集中的每个图像 SHA 均不出现在训练集中。结果：2,832 条训练记录（data/devbench/train_sft.jsonl）和 501 条零 SHA 重叠的验证记录——零 SHA 断言已通过程序验证。

然而，两种外推失败同样值得关注。其一，绝对分数不可迁移：densematch 分数比 testp1 高约 40 分（偏移量 ≈ 40），排除了用该评测台预测原始 testp1 性能的任何可能。其二，评测台无法跨训练机制外推。干净并集 s30 在 densematch 上得 83.90（高于所有单模型），densematch 也能正确识别同机制内的并集成员排序；然而在 testp1 上，s30 仅得 43.85——远低于冠军 s15（50.26）。根本原因在于 s30 在 train'（90% 数据，无过采样）上训练，处于与 s15（完整 train-dev，有过采样）结构性不同的机制中。densematch 在干净 train' 机制内将 s30 评为最优，却无法预见"完整 traindev + 过采样"机制将额外带来约 6–7 分的提升。s30 并集中的联合格式成员进一步压低了 testp1 PEM（39.08 vs s01 的 42.83），这一失败模式对 densematch 而言不可见。

认识论：同条件排序器，而非选择器

GATE-B 的持久教训是对离线评测台在该场景下能力边界的精确刻画：

  • 能做到：对相同条件下训练的模型排序（相同数据、相同损失、相同过采样机制）——三个干净的 Phase C 校准点确认了这一点；离线淘汰大的坏方向（更高图像分辨率、少数类抑制、2 轮过拟合均在 densematch 上大幅下降，每项均可节省一次 Codabench 提交）。
  • 做不到：预测绝对 testp1 分数（偏移量约 40 分）；跨机制外推（train' vs 完整 traindev、有无过采样、联合格式 vs 逐句格式）；在榜单顶端排序（500 条记录的评测台对榜首 0.3–0.5 分的差距缺乏足够统计功效）。
基于图像不相交、testp1 形状数据构建的离线评测台是一个同条件排序器。它能以低成本淘汰坏方向，并确认固定机制内的相对排序，但在跨训练机制比较候选模型或解决榜首次半分差距时，它不能替代真实排行榜评测。

累积协议（Phase C）是干净的长期解决方案：每个新候选模型均在图像不相交的 train' 上训练，离线在 densematch 上打分，同时提交至 Codabench。每组这样的配对都在无泄漏的前提下收紧了秩相关估计，且首个密度匹配模型同时充当突破性候选（P1）。评测台的可信度随干净校准点数量的增加而提升，而不依赖于事后无法去泄漏的遗留 adapter。

4 符号反转：损失函数比较中的机制颠覆

本研究过程中反复出现一种危险的符号反转现象：在某一条件下得出的实验结论，当单个上游变量改变时便会完全翻转。softmin-PEM 损失与普通交叉熵（plain-CE）之间的对比提供了最典型的案例——在三个清晰分离的训练设置下，结论方向发生了三次反转。

背景：两种损失函数

自定义的 softmin-PEM 损失（已集成进 ms-swift 4.2.3）在逐词元 CE 目标上额外添加了段落级瓶颈项。其设计意图是惩罚模型在原本预测正确的段落中产生任何假阳性少数类预测，从而保护 PEM（段落精确匹配）。Plain-CE 则是标准的逐词元交叉熵，不含任何段落感知的正则化机制。

反转一——图像不相交 train'，无过采样（GATE-B PHASE C 评测台）

在 PHASE C 中，两种损失均在 data/devbench/train_sft.jsonl 上训练：该数据集是 train-dev 的图像不相交 85% 划分（train'），未进行少数类过采样。在 densematch 离线评测台上，plain-CE 模型（A1）得分 81.13，softmin 模型（A0）得分 78.97，plain-CE 领先 +2.16。同样的排序在 testp1 上得到印证（s32 plain-CE 38.68 vs. s31 softmin 34.21，+4.47），确认了评测台的方向一致性。无过采样时，plain-CE 胜出。

在干净模型上确认 plain-CE > softmin 之后，下一步自然是将 s15 的逐句子成员以 plain-CE 在完整 train-dev 加过采样条件下重新训练（s01 方案：--minority-oversample 3.0 --supported-downsample 0.6）。结果完全反转：

反转三——架构交互（Gemma-4-26B）

在另一架构上出现了幅度更大的第三次反转。Gemma-4-26B 使用 softmin 训练得分 44.69（s26）；同一架构改用 plain-CE 重新训练仅得 21.40（s36），仅预测出 46 个少数类句子，性能几乎退化至 trivial 水平。Qwen3-VL 在过采样下使用 plain-CE 会对少数类过度触发，而 Gemma 使用 plain-CE 则灾难性地严重不触发——这表明损失函数×模型架构×过采样之间的交互关系无法跨架构外推。

机制：为何 softmin 仅在过采样下才有收益

过采样将少数类句子复制 3–6 倍，从而系统性地将梯度信号偏向少数类。在 plain-CE 下，这种偏置在推理时直接转化为少数类激活率的提升：模型大量触发少数类预测，产生假阳性，导致原本正确的段落被打碎，PEM 崩溃。softmin-PEM 损失恰好抑制了这一效应：其段落级惩罚压制了过采样引入的假阳性冗余，在保留真正少数类召回的同时恢复 PEM。当没有过采样时（PHASE C 的 train' 模型），少数类频率低，假阳性风险低，瓶颈惩罚项只是额外开销——因此 plain-CE 胜出。

当且仅当少数类过采样激活时，softmin 损失才物有所值。 任何基于干净评测台或无过采样条件的两者比较结论，均是机制条件下的局部信号， 必须在完整真实方案上重新验证后方可采纳。

即便是冠军 softmin 并集（s15），仍存在任何损失选择都无法消除的持续召回缺口。考察最优单模型（s01），其在 testp1 上的逐类召回如下：

根本性的召回瓶颈并非损失函数或过采样的产物，而是训练数据伪先验所致： train-dev 中多少数类段落的近乎缺失，使模型习得了近似确定性的"每段 ≤1 个少数类"启发规则， 这一规则单凭任何损失函数均无法克服。

5 结论

有效的方向

  • 多样模型并集集成（召回累加）。将独立训练的 Qwen3-VL-8B 成员通过 ensemble_union.py --min-votes 1 合并，是唯一在每次新增成员时均能单调超越最优单模型的杠杆：s01 47.80（1 个成员）→ s11 48.22（3 个）→ s14 49.99（4 个）→ s15 50.26（5 个）。提升在 Macro-F1 和 PEM 上同步出现，原因在于 testp1 少数类密集段落中 PEM 是召回关键：捕获一个所有其他成员均遗漏的 gold 少数类句子，可将一个 PEM=0 的段落转变为 PEM=1 的候选。一致性投票（≥2 票，s16=47.29）始终表现更差，证实了抑制策略消除的正确召回多于其消除的假阳性。
  • 过采样下的 softmin-PEM 损失。在真实训练配方（少数类过采样 + Supported 下采样）下，自定义 softmin-PEM 瓶颈损失发挥了关键作用：它抑制了普通交叉熵因过采样引发的假阳性爆炸。在 full-traindev + 过采样设置下，softmin 在单模型层面比 plain-CE 高出 +4.93（s01 47.80 vs s33 42.87），在并集层面高出 +1.72（s15 50.26 vs s37 48.54）。其机制体现在 PEM 上：s33 PEM=37.03 vs s01 PEM=42.83——plain-CE 过度触发少数类，破坏了干净段落。
  • 召回关键训练配方。最大化正确少数类预测数量是单调优化目标。抑制扫描实验清晰地说明了这一点：将少数类强制归零得到全-Supported trivial（s05=18.85）；每逐步恢复正确的少数类预测，分数单调上升——46 个少数类→18.85，127 个→38.48，171 个→39.57，190 个→43.85，253 个→47.80。核心洞察在于：testp1 段落较长（均值 8.7 句，最长 31 句），少数类密集（约 84% 的段落至少包含一个 gold 少数类），因此提升 PEM 需要捕获这些少数类句子，而非通过抑制预测来保护干净段落。

持久性经验

数据先验胜过模型规模。训练集中存在近确定性的「每段至多一个少数类」模式（99.54% 的长段落 ≤1 个少数类；完整 3333 条记录中仅 8 条含 ≥2 个少数类句子）。每个模型——无论大小或架构——都会习得这一先验。在相同数据上训练的 Gemma4-31B 比 8B 模型更保守，而非更少，仅产生 87 个少数类预测，得分 29.28。在不改变训练信号的前提下扩大模型容量无法突破召回上限。
召回关键 PEM：抑制陷阱是指标特有的。PEM 仅在段落内所有句子标签均正确时才奖励整段。在 train-dev 上（短段落，trivial=43.2），PEM 由干净的全-Supported 段落主导——抑制少数类保护了这些段落并提升了 PEM。在 testp1 上（长段落，trivial≈18.85，约 84% 含少数类），同样的抑制策略破坏了 PEM，因为遗漏的少数类句子使段落永远无法达到 PEM=1。任何基于 train-dev 统计得出的 benchmark 或框架，都会为 testp1 给出错误的抑制建议。
  • 离线评测台（densematch）是同条件排序器，而非选择器。图像不相交、testp1 形态的 dev 切分（GATE-B）能正确对相同条件下训练的模型进行排序：softmin < plain-CE < union 在 densematch（78.97 < 81.13 < 83.90）和 testp1（34.21 < 38.68 < 43.85）上均成立。然而它无法预测 testp1 的绝对分数（偏移约 40 分），且跨训练设置排名失准：它将联合锚定的干净并集（s30）评为最优候选，而该并集在 testp1 上仅得 43.85，低于 s01 的 47.80。偏移的解释是：full-traindev + 过采样相比 train'-only + 无过采样价值约 9–13 分，这一差距评测台无法建模。
  • 在真实配方上重新验证干净评测台的发现，再下结论。本次实验产生了三次符号反转：（1）veto/抑制在 train-dev 上有益 → 在 testp1 上有害；（2）在干净无过采样评测台上 plain-CE > softmin → 在真实 full-traindev + 过采样配方上 softmin > plain-CE（单模型 +4.93，并集 +1.72）；（3）联合格式在 densematch 上优于逐句格式 → 由联合成员引导的并集在 testp1 上表现不佳。每一个干净评测台的发现都应视为假设，需经 testp1 确认后方可投入训练资源。

当前最优与开放方向

永久性性能下限为：s15（5-Qwen 并集）50.26（MF1=57.17，PEM=43.34）和 s01（单模型，softmin grid）47.80（MF1=52.77，PEM=42.83），均在 full train-dev 上配合少数类过采样和 softmin-PEM 损失训练。这代表 38 次 Codabench 提交和 17 个 LoRA adapter。

剩余的召回瓶颈具有类别特异性：Supported 召回 ≈99.5%，Unsupported Causal Mechanistic ≈100%，Unsupported Entity ≈86%，Scope Overgeneralization ≈63%，Contradiction ≈22%（约在 9 个 gold 实例中命中 2–4 个）。Contradiction 和 Scope Overgeneralization 是制约 Macro-F1 进而制约总分的核心瓶颈。

以下两个方向尚未在 testp1 上测试，仍为开放选项：

  • 逐句 softmin 成员上的自洽采样。Phase-C 证明，自洽采样（温度采样 + 逐句并集）在干净无过采样评测台上可带来 +1.4 提升，且不引入相关假阳性。应用于现有 s15 softmin 成员——其 PEM 已受控——这可能在不产生联合模型自洽采样所观察到的假阳性爆炸的情况下，为 Contradiction 和 Scope Overgeneralization 提供累加的少数类召回。
  • 更多种子多样化的 softmin Qwen 成员。从 s01 到 s15 的单调扩展，完全由五个 Qwen3-VL-8B softmin 模型驱动，这些模型使用不同的过采样配置（grid / os4 / per-class / joint-8B / joint-32B）训练。在保持 softmin-PEM 损失和 full-traindev 配方的同时，使用额外种子或过采样变体重新训练，可能延续这一扩展趋势——因为每个新成员在不引入较弱架构相关噪声的情况下，减少了 Contradiction 和 Scope Overgeneralization 的零召回实例。

Phase 2 展望

Phase 2（隐藏测试集，2026-06-11 放出，截止日期 2026-06-20）引入了方向未知的分布偏移。Phase 1 的经验——在 train-dev 上校准的 benchmark 为 testp1 给出了完全相反的抑制建议——有力地支持将鲁棒性置于进一步压榨 Phase 1 分数之上。并集策略在结构上具有鲁棒性：在不同条件下训练的并集成员覆盖不同的失效模式，而 min-votes=1 确保每个成员的召回是累加的。那些在 testp1 上仅略高于 s15、却依赖配置特异性调优（分辨率、过采样率、架构特定损失调度）的候选方案，其 Phase 2 风险高于通过正交召回达到相同分数的更宽泛、更多样的并集。
