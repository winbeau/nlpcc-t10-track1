预测错误样本 & 多模判断冲突 — 根因分析

实际逐张读证据图诊断 77 例，把"召回崩塌"拆成可修惰性 vs 视觉天花板

STATUS · FINAL DATE · 2026-06-16 METHOD · 112 agents / 2.87M tok / 读图诊断 SCOPE · 52 dev-gold 错例 + 25 testp1 十模冲突
TL;DR

错误的本质是召回崩塌，不是判错类：干净模型逐类召回 CON .22 / SO .66，65% 错例是"gold 是少数类、模型判了 Supported"。

这是泛化鸿沟而非能力上限：记忆数据的 leaky 模型 CON 召回 .86、SO .84——模型有能力表示这些类，只是没学会泛化。把 43 个真模型错逐例读图拆桶，42 个可修（实体缺席核对 / 量词拆解 / 子句分解 / 去惰性），只有 1/77 真卡在 8B 读不清图（OCR）。

结论：下一步主攻应是把"实体缺席检测 + 复合句逐子句判 + 量词分解"做进训练目标（纯加法召回，命中 53/77 例），而不是堆视觉 / OCR。

01方法与数据

本次分析全程在本地完成（不动远程 GPU）：从 H200 服务器拉下 10 个差异化模型的 testp1 逐句预测、clean phaseC 模型与 leaky s01 的 devbench 预测、以及 1128 张相关证据图（62MB）。先做量化对账（官方 evaluate.py 口径，any-of 匹配），再用 multi-agent 流水线对 77 个精选案例逐例实际读证据图诊断根因，争议案例（gold 存疑 / 模型其实对了）由 opus 对抗式二次读图复核。

其它关键统计：

  • 置信度救不了：52% 干净错例 min_logprob > −0.05（p>0.95），是"自信地错"——置信度阈值 / 弃权无效。
  • SO↔UE 混淆大半是合法多标签：gold 里 SO+UE 共现 348 次（最大多标签对；全体多标签仅占 3.0%），所以 SO→UE 不全是错。
  • union 召回收割：单模 flag 少数类占 4.8% → 10 模并集 11.5%（+139%），但 precision 无 gold 不可验。

dev 错例被 ENTITY(15) + GOLD_ERROR(12) + SCOPE(12) 三分天下——其中 GOLD_ERROR 占 23%，是"我们其实对了"。testp1 冲突被 CAUSAL(10) + ENTITY(8) 主导，且 GOLD_ERROR = 0：十模分歧不是标注噪声，而是真·难判句。

04召回崩塌的真因

核心：CON .22 / SO .66 的崩塌是"泛化鸿沟 + DEFAULT_TO_SUPPORTED 惰性"，不是"8B 看不清图"的能力上限。memorized 模型拿 CON .86 / SO .84 证明这些句在容量内可判——干净模型不是不能判，是没学会判。把 43 个"真模型错"（已剔除 gold 噪声与 UNCLEAR）按"是否真需 8B 力不能及的视觉"拆桶：

需求类型真错例可修性
文本/结构接地（核对句中图号·指标名 vs caption/表头）17完全可修，不需更强视觉
量词/范围推理（SO，把 "all" 拆逐条核验）11可修（训练目标 + 分解）
子句分解（CAUSAL，独立评每个子句）7可修（复合句独立判 + 标记词）
DEFAULT_TO_SUPPORTED 纯惰性5可修（去 SUP 先验）
真·像素读图（NUMERIC_OCR：两行数字方向比较）18B-VL 受限，需 OCR 通道
modality 标签有误导

image_numeric 在 77 例里占 32 个，看似"必须强读图"。但逐例核查后，那些 image_numeric 的 ENTITY 错其实只需对照表头字符串（句子说 Top-5、表里只有 Top-1）——属文本接地，不是 OCR。为何 memorized .86 而干净 .22：训练数据"每段 ≤1 个少数类"的伪先验形成强 SUP 默认；s01 是记住 dev 答案而非学会判别。所以杠杆是"教会判别 + 拆掉 SUP 先验"，不是"换更大模型"——这也解释 31B 单模 s27=29.28 还不如 26B：堆容量对惰性偏置无效。

05多模判断冲突的本质

结论：testp1 十模分歧 ≠ 图不清，≈80% 是真实的「标签定义边界」之争，由模型激进度差异放大。

  • 不是图不清：冲突例 figure_readability = numbers_legible 18/25（72%），no_relevant_content 仅 4 例（且多靠 caption 即可定 CON）。
  • 冲突 label-pair 暴露定义边界：前两大对（SUP-vs-某少数类）= 召回战场（一个模型敢开、其余惧 SUP）；SO↔UE = 纯定义边界（同一短语既可读成"越界"也可读成"缺失实体"）。
  • 17/25 冲突例裁为 model_defensible：少数票模型其实抓对了，保守的多数票漏了。

激进 vs 保守是放大器而非根因：单模少数类调用率从 Qwen32B-joint 3.6% 到 Gemma-26B 7.5%（2 倍差）。激进模型在 caption-driven 的 CON 例上偶尔 SUP 误火，但在 ENTITY/UCM 例上往往是它们抓对、Qwen32B-joint 孤票漏。这正是 union ensemble 历史有效、而保守后处理单调掉分的微观原因：分歧主要落在"敢不敢开少数类"，并集恰好收割了激进模型的正确召回。

句称 "12 层是 current graph transformer 的上限"，但图里作者自己的 DeepGraph 撑到 45+ 层，只有 baseline 退化 → 把"基线失败"外推成"所有架构失败" = SO。

t1:…-000027:s0CAUSAL · 10 模全判 UCM

柱状图确显两剂量都赢 placebo（前半事实对），但尾句 "dose-independent therapeutic mechanism targeting mucosal healing" 是机制推断，柱状图给不出 → UCM。

07Gold 噪声 / 模型其实判对了

dev 错例里 约 29%（15/52）经对抗式读图核实为标注噪声或本质歧义（confirm_contested 12 + 正解实为 UNCLEAR 5，去重）。对抗复核总览：confirm_contested 27 vs reject_contested 6——争议案里 82% 站在"模型/争议方有理"一边。

08可操作杠杆（按期望收益排序）

收益判据 = 命中"可修桶"的真错例数 × 可实现性。所有杠杆都瞄准召回（catch 长段里的真少数类），与 testp1 RECALL-critical 一致；不碰任何抑制类后处理。

#杠杆命中桶覆盖真错收益
1实体缺席检测：训练注入 negative 对（句中 token vs caption/表头字符串核对）；推理加一步"句中每个命名实体是否在证据中？"ENTITY_PRESENCE23高
2复合句逐子句独立判 + UCM/因果标记词（mechanism / governs / suggesting that / exclusively → UCM 候选；任一子句无据则整句非 SUP）CAUSAL_CLAIM14高
3量词分解（all / significantly / full range 拆逐条核验；先做实体在场检查排除 UE → 强制走 SO）SCOPE + SO↔UE 边界16中-高
4去 DEFAULT_TO_SUPPORTED 先验（清洗"每段≤1少数类"伪先验 + 密度匹配长段训练）惰性偏置5 + 全局中（PHASE C 密度匹配已过门 +2.68 densematch）
5清洗 gold 训练噪声（UE↔UCM / header / caption-paraphrase 三类重标）GOLD_ERROR12（训练侧）中

一句话

召回崩塌 ≈95% 是惰性而非失明；最高 ROI = 把"实体缺席检测 + 复合句逐子句判 + 量词分解"做进训练目标（杠杆 1-3，命中 53/77 例），全为纯加法召回、零抑制，与 testp1 RECALL-critical 和已过门的密度匹配方向一致。真·读图瓶颈（OCR）只占 1/77，不值得当主攻。
