# 破局升分调研(突破 s15=50.26)

> 2026-06-04,multi-agent workflow(15 agent:7视角发散 → 收敛 → 6路对抗核实 → 计划)。**对抗核实在本地 jsonl 上实算证伪了多数"便宜后处理",结论比直觉更硬。**

## 🔴 已死(零成本即判,别再碰)

**所有"抑制类"后处理 = 数学上等价已证伪的 s16/veto。** 决定性证据(本地实算):
- s15 的 **382 个少数类预测里 109 个是单成员单票(1/5)**;s16(≥2票共识)把它们砍掉 → 50.26→47.29(**−2.97**)。若这些单票是"打碎段落的 FP",砍掉后 PEM 应**升**;实际 PEM **降** → **这 109 个单票净为真阳。testp1 的 PEM 是召回受限,不是精度受限**。任何"删少数类→Supported"的动作在 PEM 上单调亏。
- **两阶段路由 ≡ s15**:union 已是每个成员的严格超集(s15-干净段 ∩ s01-脏段 = 0),完美二分路由器 = s15 = 50.26,零增益。
- 段落预算门控 / 自洽频次门控的"滤抖动 FP"主臂 → 同理是抑制,死。

## 🟡 重要修正:"置信门控 union"(我和 augment 调研都推过的 P0)没那么简单
- 对抗核实实算:s23 比 s15 多的 116 个少数类 = **48 落在 s15-脏段 + 68 落在 s15-干净段**。
- **"脏段加少数类对 PEM 零风险"是错的**:一个脏段在 s15 下可能本来全句对(PEM=1),在它某 Supported 句上多开一个 FP 就打成 0。
- 严格 PEM-safe(以 s15 为下界)的门控版 → **退化成 s15 本身(仅 1 句可改)= 零增益**;非 PEM-safe 版 PEM 符号不定。
- → **置信门控 union 不是稳赢的便宜招;它到底能否 >50.26 必须有 gold/离线台才能定**(见下 GATE-B)。

## ✅ 根因发现(已核验,金子):"≤1 少数类/段"的伪先验
- **traindev 1303 个长段(≥6句)只有 6 个含 ≥2 少数类(0.46%);全 3333 段只有 8 个 record 含 ≥2 少数类。**
- 模型因此学到近确定性的伪先验「一个长段至多 1 个少数类」。这**同时解释**了:召回天花板(密集长段里只敢开 1 个)+ union 的 FP 打碎 PEM(每成员只敢开 1 个、且对开哪个意见不一 → 并集凑数=FP)。
- 正交于已证伪的过采样(s07-s10 只改单句类频、段落几何丝毫未动)。

## 🔑 GATE-B 离线台(最高 ROI 元突破;evalbench-design workflow 正在专门深挖)
- GATE-A 只做了 image-disjoint(去图泄漏)但**分布几何仍失配**(traindev 段短/稀 vs testp1 段长/密)。
- **GATE-B = image-disjoint + testp1-shaped 重采样**(只保留/上采样 段长≥8 且少数类密集的记录,使 devhard' 段长&少数类密度直方图 ≈ testp1)。
- **关键:用已知的 11+ 个 testp1 真分数做 rank-correlation 校准**(s01<s11<s14<s15、s18/s23<s15…)——台子可信 ⟺ 它对这些提交的排序 ≈ testp1 排序。这把"绝对分≠testp1"的问题绕开(只要排序对就能选型)。

## 立即可做(零成本 linchpin)
1. **验证伪先验(10 分钟、免费)**:跑 s01 grid 对 testp1 推理,统计**每段预测出的少数类句数直方图**。若 ≥95% 段最多 1 个少数类 → 伪先验坐实 → P1 密度匹配是最高价值方向。
2. **拉 raw 到本地**:`outputs/` 本地为空,后处理原型需要 5 个成员的 raw(含 min_logprob)→ 从服务器拉。
3. **纪律**:每发盲交前 `validate_submission.py` + 顶回 s01 保底;Phase-2(6/11 放出)别过拟合 Phase-1;s01(47.80)/s15(50.26)永久保底。
